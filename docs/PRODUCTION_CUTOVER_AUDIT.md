# GARI AgriTech Platform — Production Cutover Audit

**Document**: Production Cutover & Readiness Audit (`docs/PRODUCTION_CUTOVER_AUDIT.md`)  
**Date**: November 2026 (GARI 2.0 Initiative)  
**System Target**: Transition from Demo/Test Staging to Real Production Operations  
**Auditor**: Principal Software Architect & QA Lead  

---

## 1. Executive Summary

This audit identifies every instance of demo data, seed scripts, fake users, test organizations, mock payment behavior, hardcoded test quotas, and development bypass flags across the GARI AgriTech codebase and database (`database/disease_detector.db`).

All findings are strictly categorized into three tiers:
1. **Confirmed Demo/Test Data** (Safe for automated cleanup)
2. **Real User & Business Data** (Must be protected and preserved)
3. **Uncertain Records** (Requires owner approval; strictly preserved during initial cutover)

## 3. Codebase Audit: Seed Scripts, Demo Flags & Mocks

### 3.1 Demo Scripts & Startup Hooks
1. **`database/seed_dev.py`**:
   - Status: Development utility script that seeds `danhuynh@gari.vn` and `nongdan.mau@gari.vn`.
   - Security Risk: Contains hardcoded demo passwords (`Password123!`, `FarmerPassword123!`).
   - Remediation: Remove any auto-invocation from application boot. Add strict environment check: prevent execution when `APP_ENV=production`.
2. **`init_db.py`**:
   - Critical Risk: Lines 13–15 contain `if os.path.exists(DB_PATH): os.remove(DB_PATH)`.
   - Remediation: Add mandatory production guard requiring `APP_ENV != 'production'` and `--force-drop-database` CLI argument before dropping database.

### 3.2 Demo Bypass Flags
1. **`X-Gari-Dev-Pro` and `?dev_pro=1`**:
   - Location: `api_server.py` lines 3075–3077 and `gari_plans.py`.
   - Audit Finding: In development, allows bypassing VIP subscription checks.
   - Production Guard Status: Already protected by `gari_config.ALLOW_DEV_PRO_BYPASS = False if IS_PRODUCTION else ...`.
   - Remediation: In `api_server.py`, ensure that when `APP_ENV=production`, `request.headers.get('X-Gari-Dev-Pro')` and query param `dev_pro` are completely ignored and stripped, regardless of configuration.

### 3.3 AI Model Inference Verification
1. **Model Discovery**:
   - 51 deep-learning models discovered in `models/` with valid `.safetensors` checkpoints.
   - Leaf validation optical gate (`gari_inference_engine.py`) rejects non-leaf inputs with botanical multi-spectral indices (`NOT_A_LEAF`, `IMAGE_QUALITY_LOW`).
2. **No Fabricated Model Output**:
   - Confirmed that diagnosis inferences are executed on actual PyTorch neural nets.
   - If a model is not found, `gari_inference_engine.py` raises `ValueError`/`RuntimeError`, which `api_server.py` translates to clear error responses.
   - Low-confidence results are labeled as `UNCERTAIN` or `crop_uncertain` rather than inventing false certainty.

### 3.4 Payment & Subscription Verification
1. **No Fake Payment Success**:
   - User clicking "Tôi đã chuyển khoản" triggers `report_user_transfer`, which sets status to `pending_review`.
   - **Crucial Invariant Verified**: It does NOT activate VIP or credit turns automatically.
   - Real VIP activation occurs solely via `admin_confirm_payment` executed by an authenticated Host Administrator with audit logging, or via verified cryptographically-signed provider webhooks.
